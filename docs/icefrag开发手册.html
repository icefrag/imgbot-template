icefrag 开发手册

一、快速上手

1. 初始化环境

装一次, 以后所有项目通用:

  • uv(包管理器): pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple
  • 已装 Python 3.12+ 的话 uv 直接用它, 不再下载;
  • 解压骨架 zip 到任意目录, 比如 D:\scripts\我的挂机。

    • (机器上有 Python 就能用它装; 没有 Python 也行, uv sync 会自动从南大镜像下载);

    2. 安装依赖

    在骨架目录执行:

    uv sync

    骨架自带的两个 wheel 在 libs/ 里(脚手架 + 引擎), 从本地文件安装; 其余公共依赖自动从清华镜像拉。全程不需要访问 GitHub。

    3. 测试启动

    uv run console.py

    中控台是唯一入口(单开多开都是它): 鼠标悬停在目标窗口上按 F9 → 收编进表格并启动; 表格行按钮启停; 右侧日志流; 再按 F9 收编下一个即多开。 adb 端(模拟器/真机)是另一套打法: 在线设备整表自动入列、按行启动, 没有热键收编——模拟器/真机用户直接跳四章。

    二、写你的业务

    4. business.py: 参数面板

    一个 dataclass = 全部业务参数, FIELD_META 声明中文名与控件类型, 中控台的设置弹窗自动生成(用户改值自动落盘 business.yaml):

    from dataclasses import dataclass

FIELD_META = {
    "attack_wait": ("等击杀秒数", "entry"),
    "max_kills":   ("最大击杀数(0=无限)", "entry"),
    "pick_coin":   ("捡金币", "combo:是|否"),
}

@dataclass
class BusinessConfig:
    attack_wait: float = 10.0
    max_kills: int = 0
    pick_coin: bool = True

    任务里 ctx.cfg.attack_wait 取当前值。

    5. task.py: 挂机逻辑

    main_task(ctx) 是任务主体, 顶层命令 from icefrag.dsl import * 直接用 —— 两层: icefrag 命令(组装层: 拟人键鼠/等待环/复合动作) + 大漠直通(DmSoft 全量同名同参, 仅 window 端):

    from icefrag.dsl import *

def main_task(ctx):
    while not stopped():                             # 挂机循环自己写
        hit = wait_pic("怪.png", timeout=3000)       # 等怪 (x, y, 分) | None
        if not hit:
            log("场上无怪"); sleep((1000, 2000)); continue
        click(*hit[:2])
        if wait_pic_gone("怪.png", timeout=10000):   # 等击杀
            log("击杀"); shot("kill")                # 留痕到 logs/shots

    大漠直通与大漠一字不差, 老脚本直接搬:

    idx, x, y = FindPic(0, 0, 640, 480, "领取按钮.png") # 未找到 = (-1, -1, -1)
if idx >= 0:
    MoveTo(x, y); LeftClick()
SendString(GetBindWindow(), "出售红药500金")        # 打字(老ANSI窗口加 ime=True)

    循环自己写, 返回 = 任务完成: main_task 只被框架调用一次, 正常返回即整个 任务完成收口。要挂机就自己写 while not stopped(): ...(F9 叫停循环即退); 预期内的失败(没找到怪/点击落空)在循环里 try/except 掉——那是业务; 冒出去的异常 框架才接管: 自动重开, 连败熔断。做一次性任务直接写直线代码, 不用任何技巧。

    命令权威表: PC 窗口端见三章, 手机(adb)端见四章(签名由框架内省生成, 与代码不漂移)。更冷门的动作走逃生舱: ctx.ops(图色门面, 双端同构)/ ctx.device(adb 方言, 表见四章)。

    6. 图色素材

    素材就是 PNG 和色值, 用你顺手的截图工具做, 放进 templates/ 即可: wait_pic("xx.png") / find_tap("xx.png") 按文件名引用。 找色类逻辑不需要素材, 直接写色值(吸管取色, 注意 BGR 序)。

    同源裁材: 屏幕截图的像素未必等于框架截屏的像素(后台/特殊渲染窗口)。 从 logs/shots/ 的留痕截图裁素材——那是框架眼里的画面, 同源必配。

  • 拟人语义在 adb 端: 无鼠标轨迹概念, click = 停顿前摇+落点抖动+tap;
  • 停止: adb 端用中控台行按钮停止(stopped()/sleep 可中断同一机制,
  • 通道/收编/dx 开关全是 window 端配置, adb 端天然后台不占键鼠,

    六、通道选择速查(仅 window 端)

    能力矩阵

    本章仅 window 端适用; adb 端天然全后台(截屏=adb screencap, 输入=adb shell input), 无通道概念——display/mouse/keypad 等配置不参与(见四章)。

    通道取值前台/后台占真键鼠适用与坑
    displaynormal前台—直接抓屏, 目标须可见不被遮挡, 最快最稳
    displaygdi后台—PrintWindow 让窗口自画进内存, 遮挡/被盖都能截, 通用首选
    displaygdi2后台—兼容模式慢但稳; gdi 截图不刷新/花屏时换它
    displaydx后台—潜影注入截帧(OpenGL 已通, D3D9 调试中, 不通明确报错); 需 bin/ 注入件(杀毒报毒是常态)
    mousenormal前台占SendInput 真鼠标, 兼容一切; 跑动时人不能碰机器
    mousewindows后台不占PostMessage 直投消息; tkinter 自绘类窗口不认(收编前先看清目标)
    mousewindows2后台不占dx 消息鼠标+GetCursorPos 虚拟光标锁, 治"点击坐标总落到真鼠标处"; 需注入件
    mousedx后台不占潜影注入, 检测面最小, 需注入件
    keypadnormal前台占SendInput 真键盘
    keypadwindows后台不占带扫描码消息按键(旧"死案"系误传, 已实现); 只达读消息循环的窗口, 轮询型游戏(GetAsyncKeyState)免疫
    keypaddx后台不占潜影注入, 需注入件; 轮询型目标配 hook_keystate

    选型口诀: 能 gdi+windows 全后台就全后台(测试/挂机两不误); 目标不认 PostMessage 点击再退 normal 前台; 3D 游戏上 dx。

    对症速查(与设置弹窗"经典组合"同源——单一数据源 settings.CLASSIC_COMBOS, 点按即套用):

    症状配方(display · mouse · keypad)
    起步首选 · 普通窗口后台挂机gdi · windows · windows
    移动/键盘正常, 唯独点击全无反应gdi · dx · windows + fake_active
    键盘消息全无反应(消息免疫)gdi · dx · dx + hook_keystate
    点击坐标总落到真鼠标处/偏移gdi · windows2 · windows
    GDI 截图黑屏/冻结(D3D/GL 游戏)dx · dx · windows

    八、打包与升级

    打包 exe 发给别人

    uv run build_exe.py

    产出 dist/<你的名>-v<版本>.zip: 目标机零 Python, 解压即用; templates/ 与 scaffold.toml 摆 exe 旁, 用户可自行调参。 bin/ 注入件会被 Defender 报毒, 目标机需把解压目录加入杀毒排除——发给人时记得交代。

    升级脚手架

    作者在群里发新版时:

  • 下载新的两个 whl, 替换 libs/ 里的同名旧文件(文件名里的数字就是版本号);
  • pyproject 里 [tool.uv.sources] 两行 path 改成新文件名;
  • uv sync。

    • 不领新版就继续用旧的, 互不影响。
