# 脚手架使用手册(脚本开发者版)

你拿到的是一个骨架 zip。解压、装依赖、改两个文件,就得到一个完整的挂机工具:
多开中控台、F9 收编目标窗口、异常自动重开、无进展看门狗、日志与截图留痕全是现成的,
你只写**业务逻辑(task.py)**和**业务参数(business.py)**。做完还能一键打包成 exe 发给别人用。

全程不需要访问 GitHub。

## 第 0 步: 环境准备(一次性)

1. **uv**(包管理器): `pip install uv -i https://pypi.tuna.tsinghua.edu.cn/simple`
   (机器上有 Python 就能用它装;没有 Python 也行,uv sync 会自动从南大镜像下载);
2. 已装 **Python 3.12+** 的话 uv 直接用它,不下载;
3. 解压骨架 zip 到任意目录,比如 `D:\scripts\我的挂机`。

## 第 1 步: 装依赖

在骨架目录执行:

```bash
uv sync
```

骨架自带的两个 wheel 在 `libs/` 里(脚手架 + 引擎),从本地文件安装;
其余公共依赖自动从清华镜像拉。没有网络要求以外的任何门槛。

## 第 2 步: 跑起来看看

```bash
uv run console.py    # 中控台(唯一入口): 表格启停/日志/设置
F9 收编目标, 收编几个跑几个
```

window 端的玩法: 把鼠标**悬停**在目标窗口上按 **F9** → 收编进表格并启动;
再按一次停止。adb 端(模拟器/真机)自动发现设备,无需收编。

## 第 3 步: 写你的业务(只有两个文件)

### business.py: 你的参数面板

一个 dataclass = 全部业务参数,`FIELD_META` 声明中文名与控件类型,
中控台的设置弹窗**自动生成**(用户改值自动落盘 business.yaml):

```python
from dataclasses import dataclass

FIELD_META = {
    "attack_wait": ("等击杀秒数", "entry"),
    "max_kills":   ("最大击杀数(0=无限)", "entry"),
    "pick_coin":   ("捡金币", "combo:是|否"),
}

@dataclass
class BusinessConfig:
    attack_wait: float = 10.0
    max_kills: int = 0
    pick_coin: bool = True
```

### task.py: 你的挂机逻辑

`main_task(ctx)` 是任务主体。顶层命令 `from icefrag.dsl import *` 直接用:

```python
from icefrag.dsl import *

RED = (51, 51, 204)                                  # #CC3333 的 BGR
MON_PTS = [Pt(0, 0, RED, 40), Pt(8, 0, RED, 40),     # 怪身 4 点阵, 全中才算
           Pt(0, 8, RED, 40), Pt(8, 8, RED, 40)]

def main_task(ctx):
    while not stopped():                            # 挂机循环自己写, F9 叫停即退
        hit = find_multi_color((0, 0, 900, 640), MON_PTS)   # 多点找色锁怪
        if not hit:
            log("场上无怪"); sleep(1500); continue
        click(*hit)
        if wait_color_gone("CC3333-282828",
                           region=(hit[0]-45, hit[1]-70, hit[0]+45, hit[1]+70),
                           timeout=int(ctx.cfg.attack_wait * 1000)):
            log("击杀"); shot("kill")                        # 截图留痕到 logs/shots
```

三条铁律:

- **凡时间皆毫秒**: `sleep(500)` = 半秒;
- **找不到不抛异常**: find/wait 失败返回 None/False,"没找到"是挂机常态,
  真故障交给框架自动重开兜底;
- **F9 停止贯穿一切等待**,按下即醒即退。

**循环自己写,返回 = 任务完成**: main_task 只被框架调用**一次**,正常返回即整个任务
完成收口。要挂机就自己写 `while not stopped(): ...`(F9 叫停循环即退);
预期内的失败(没找到怪/点击落空)在循环里 try/except 掉——那是业务;冒出去的异常
框架才接管: 自动重开(重绑重进),连败熔断。做一次性任务直接写直线代码,不用任何技巧。

完整命令表(click/key/find_tap/tap_until_gone/ocr/wait_pic/...)见骨架附带的
`docs/DSL语法清单.md`——那是权威版,常用动词在 `dsl.py` 模块头也有速查。

想深挖: `ctx.ops`(图色门面)/`ctx.dm`(DmSoft 全量接口)/`ctx.device`(adb 魔神方言)
是逃生舱,能力一分不少。

## 第 4 步: 制作图色素材

素材就是 PNG 和色值,用你顺手的截图工具做,放进 `templates/` 即可:
`wait_pic("xx.png")` / `find_tap("xx.png")` 按文件名引用。
找色类逻辑不需要素材,直接写色值(吸管取色,注意 BGR 序)。

## 长跑保障(白送的, 知道即可)

| 机制 | 干什么 | 哪里调 |
|---|---|---|
| 异常自动重开 | 任务抛异常自动重启,连败超限熔断躺平 | scaffold.toml `max_restarts` |
| on_fuse 钩子 | 熔断前给你一次自愈机会(重启游戏/重登),写 task.py 里 `def on_fuse(ctx) -> bool` | task.py |
| 无进展看门狗 | 画面卡死没异常也逃不过,超时自动停+截图 | scaffold.toml `idle_timeout` |
| FatalError | `raise FatalError("封号")` 致命场景直接停,不白烧重开次数 | task.py |
| 截图留痕 | `shot("标签")` 与失败自动截图,都进 logs/shots | 自动 |

通道、热键、主题等框架配置在 `scaffold.toml`: 通道与绑定开关**下次收编生效**
(不用重启中控台),热键/主题保存即生效。通道怎么选见下节。

## 窗口绑定通道(对症下药)

window 端绑定 = 通道三件套 + 绑定后开关。设置弹窗里每个绑定项都有 `?` 悬浮讲解、
底部"经典组合"点一条即套用;本节是完整版,两边文案同源。

### 通道三件套(dm.BindWindow 的 display/mouse/keypad)

| 字段 | 取值 | 作用 | 使用场景 |
|---|---|---|---|
| `display` | `normal` | 前台截屏裁剪 | 目标必须前台可见 |
| | `gdi` | PrintWindow 后台截图 | 默认首选, GDI 窗口通吃 |
| | `gdi2` | 兼容模式, 慢但稳 | gdi 截图不刷新时换它 |
| | `dx` | 注入件截帧(OpenGL 已通) | GDI 截不到的游戏; D3D9 调试中, 不通会明确报错 |
| `mouse` | `windows` | 宿主侧 PostMessage | 门槛低, 普通窗口首选 |
| | `dx` | 注入件进程内合成 | 消息要过游戏输入检查的目标 |
| | `windows2` | dx 消息 + 虚拟光标锁 | 点击总落到真鼠标处/偏移 |
| | `normal` | SendInput 真事件 | 最后手段, 动真光标且须前台 |
| `keypad` | `windows` | PostMessage 消息键盘 | 默认首选 |
| | `dx` | 注入件合成 | 配合键状态钩子治无反应 |
| | `normal` | SendInput 真事件 | 最后手段, 动真键盘 |

### 绑定后开关(需 dx 系通道, 非 dx 时警告跳过)

| 字段 | 治什么病 | 症状/场景 |
|---|---|---|
| `fake_active` | 让后台窗口被游戏视为激活, 绕过点击处理里的激活门槛 | 移动/键盘都正常, 唯独点击全无反应 |
| `hook_keystate` | 钩住 GetAsyncKeyState, 游戏轮询按键状态、不收消息时才需要 | 键盘消息全无反应 |
| `hide_module` | 把注入件从目标进程的模块列表里藏起来 | 反作弊扫模块时; 绑定后调一次即可, 平时保持 `false` |

### 经典组合(按此顺序试, 能用上面的别用下面的)

| 症状/场景 | 配方(display · mouse · keypad) |
|---|---|
| 起步首选 · 普通窗口后台挂机 | `gdi · windows · windows` |
| 移动/键盘正常, 唯独点击全无反应 | `gdi · dx · windows` + `fake_active` |
| 键盘消息全无反应(消息免疫) | `gdi · dx · dx` + `hook_keystate` |
| 点击坐标总落到真鼠标处/偏移 | `gdi · windows2 · windows` |
| GDI 截图黑屏/冻结(D3D/GL 游戏) | `dx · dx · windows` |

### 硬约束

- 解绑收口(`UnBindWindow`)框架已在任务结束时自动执行, 不用管;
- `EnableRealMouse/EnableRealKeypad/EnableMouseSync/EnableKeypadSync` 是恒返 1 的
  大漠兼容占位,**不是开关**, 别配置;
- 引擎未实现的方法(变速/锁输入等)显式 raise, 不是静默失败;
- 目标提权运行(管理员)时宿主也必须管理员, 否则全被 UIPI 拒(err=5);
- 诊断渲染是否活着: task 里直调 `ctx.dm.GetFps()`(dx 图色, 一秒帧序号增量)。

## 打包 exe 发给别人

```bash
uv run build_exe.py
```

产出 `dist/<你的名>-v<版本>.zip`: 目标机**零 Python**,解压即用;
`templates/` 与 `scaffold.toml` 摆 exe 旁,用户可自行调参。
**bin/ 注入件会被 Defender 报毒**,目标机需把解压目录加入杀毒排除——发给人时记得交代。

## 升级脚手架

作者在群里发新版时:

1. 下载新的两个 whl,替换 `libs/` 里的同名旧文件(文件名里的数字就是版本号);
2. pyproject 里 `[tool.uv.sources]` 两行 path 改成新文件名;
3. `uv sync`。

不领新版就继续用旧的,互不影响。

## 常见问题

- **要访问 GitHub 吗?** 不用。你的依赖全在 zip 里和清华镜像上。
- **素材明明截了却匹配不上?** 屏幕截图的像素未必等于框架截屏的像素(后台/特殊渲染
  窗口)。从 `logs/shots/` 里的留痕截图裁素材——那是框架眼里的画面,同源必配。
- **F9 收编错了窗口/收编到子控件?** 用 `uv run python tools/pick_probe.py`
  实时看 hover/focus 两种模式各拾到哪个窗口(句柄/类名/标题),
  据此改 `scaffold.toml` 的 `pick_mode`(悬停类窗口选 hover, 嵌套子窗口选 focus)
  和 `window_class`(类名过滤串)。
- **杀毒报毒?** 注入件的工作性质决定的,加排除目录即可(见上)。
- **支持哪些目标?** PC 窗口(window 端,含后台通道)与安卓模拟器/真机(adb 端)。
  tkinter 自绘类窗口后台点击不认,选通道前先用 pick_probe 看清目标是什么窗。
- **我是谁?** 写 task.py 的你是脚本开发者;你把 exe 发给的人是脚本使用者,他不用看本手册。
