# 库化分发: 引擎闭源 wheel + 脚手架开源 + 文件分发

脚手架从"拷贝整目录即新项目"的模板形态,翻转为"薄项目依赖框架包"的库形态。分层定边界: 引擎层(imgbot+潜影)编译成闭源 wheel 保机密,脚手架层(bot/)以源码随骨架 zip 开源做推广物料;国内脚本开发者经群文件/网盘拿骨架 zip 里的 libs/*.whl 离线安装(三方依赖走清华镜像),全程不碰 GitHub——GitHub 降级为作者源码备份与面向世界的门面。作者本人 dogfood 仍用 path+editable 直链,同一薄项目形态、两条依赖通道,靠各项目自己的 [tool.uv.sources] 覆盖切换。

## Considered Options

- **延续拷贝模板**: 隔离性好,但框架修 bug 五个项目改五遍,且与"给大家用"的目标背道而驰。
- **全闭源单 wheel**: 大漠式商业路线可行,但吃满三代价(无补全/信任/编译维护),且把最好的推广物料(DSL 文档与可读源码)锁死。
- **全开源**: 推广最顺,机密归零,将来收费无處落子。
- **引擎闭、架子开(选定)**: 护城河黑盒、招牌敞开;将来引擎层上锁收费,不惊动任何存量薄项目。

## Consequences

- 文件分发下"不同用户不同版本"天然成立: 每人攥自己的 whl 文件,不领新版不被动升级;uv 锁 wheel 哈希防偷换。
- 每次发版前必须按用户姿势自测: 干净目录解压骨架 zip → uv sync → 冒烟通过才发群。
- 引擎层要养编译管线(Cython/Nuitka 出 .pyd, 每个 Python 版本一编)并配 .pyi 桩保 IDE 补全;脚手架层零编译,纯源码。
- 包名定为 `icefrag`(取自作者 GitHub 同名成品牌, `from icefrag.dsl import *` 顺口);
  已随本仓翻转完成 `bot/`→`icefrag/` 改名(2026-10),趁零外部用户时改的。
