# 任务边界: main_task 单次调用, 循环归业务

worker 曾把 main_task 当"一轮", 在外层 while 里按 loop_interval 无限重入, 轮成功清零
重开计数。现改为: 框架只调用 main_task **一次**, 正常返回 = 任务完成收口; 挂机循环
(`while not ctx.stop.is_set():`)由 task.py 自己写, loop_interval 配置项退役。

理由: ①隐式重入是惊喜式控制流——写直线代码的作者本人都被"怎么截图截个不停"坑了,
脚本开发者只会更懵; ②框架循环实际提供的只剩节拍, 值业务侧一行 sleep, 不值一条
隐式魔法; ③"轮成功清零计数"会掩盖退化(隔轮抛错的任务永不熔断, 烂着跑通宵)——
预期内失败本就该业务侧 try/except(那是业务), 冒到框架的异常才是真故障, 熔断语义
因此更准; ④领域惯例(AutoJS/按键精灵)皆任务自带循环, 平台只管恢复与停止。

保留不变: 异常重开(重绑重进)/熔断+on_fuse/无进展看门狗/F9 停止贯穿。
次生改动: worker 完成态新增"已完成"(此前正常返回只会被重开, 不存在完成态),
selfcheck 断言与出厂示例 docstring 随之更新。
