# 保障线验收: worker 保障线以真机手测为准, 不造"假 ctx"式离线单测

worker 的五条保障线——异常重开/熔断+on_fuse/无进展看门狗/FatalError 短路/F9 停止
贯穿——不建"假 ctx + 假 task"式离线单测。架构评审曾建议把 Worker._run 的循环体
解焊成可注入的 _drive(ctx, task_mod) 以便离线回归, 本 ADR 否掉该方向。

理由: ①保障线围着真绑定转——真窗口/真设备的停止语义、unbind 时序、二次绑定的
状态, 假接口测的是 Mock 的世界, 绿了不代表真机不翻车; ②本仓验收姿势历来是真机/
靶场: on_fuse 与看门狗当年就是 notepad 真机四场景手测验收的(a7d6632/eee0c99),
dummy_game E2E 盖 dsl 命令, selfcheck 盖快乐路径, 各安其位; ③离线假接口测试的
既有范围(纯函数与路由层: test_dsl_mouse/test_adb_rows)不变——本 ADR 只圈 worker
保障线, 不外推到"假接口测试无用"的全称。

## Considered Options

- **假 ctx 单测(否)**: 秒级可跑, 但测不中真险(停止/时序/重绑都在真世界)。
- **E2E 自动化保障线(否)**: 要可控地造"连续异常/卡死"靶, 靶子成本高过收益。
- **真机手测+提交留痕(选定)**: 改保障线时真机走一遍场景, 验证记录写进提交说明。

## Consequences

- 动 worker._run 保障逻辑的验收 = 真机手测, 提交说明里写验证了哪些场景;
  selfcheck 快乐路径仍照跑。
- 未来架构评审不再建议给保障线加离线单测或"解焊 _run"式重构。
- 保障线回归靠人记——若将来真因保障线翻车, 再回头修本 ADR, 优先补 E2E 靶。
